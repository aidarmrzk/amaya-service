Подтверждены конкурентная покупка без дубликата, конфликт ключа с другим тарифом (409), восстановление для своего устройства и отсутствие доступа для нового устройства. Production URL отвечает без Vercel-сессии.

## Доступ и данные

Отдельный Appwrite-проект, база amaya, таблица purchases.
Runtime-ключ: только rows.read/rows.write, закрытая конфигурация сервера.
Идемпотентный ID строки учитывает и устройство, и requestId.
API возвращает только id/offerId/createdAt. Сумма и deviceId от клиента отвергаются.
Cookie: HttpOnly, SameSite=Lax, Secure в production.
Проверка стороннего устройства — обязательная часть smoke-скрипта.

## Итоговое независимое ревью

Найден и исправлен один Important: cookie устройства теперь устанавливается
до покупки в GET /api/offers с Cache-Control: no-store. Регрессионный тест
воспроизвёл отсутствие cookie до исправления и прошёл после него.
Других Critical/Important замечаний не было.

Оставшиеся Minor: purchase retry не автоматизирован отдельным E2E-сценарием
(он покрыт unit-тестом); клавиатурный выбор не включён в E2E-набор, но
проверен вручную на публичном сервисе: ArrowDown переключил yearly на monthly,
после чего настоящий CTA открыл доступ на один месяц.

Figma открывается анонимно с правом просмотра. Production-деплой READY:
https://amaya-service.vercel.app. Браузерный набор из 8 тестов прошёл также
на опубликованном URL. Снимки: screenshots/live-390.png и live-browser.png.
Production purchase + direct DB evidence: verification-results/live-api.json.

## Принятые решения

- Работа в указанной пользователем новой папке на codex/amaya-paywall,
  без отдельного worktree: существующего продукта и общей ветки нет.
- Учёт шагов ведётся нативно в PowerShell вместо Bash helper scripts;
  результат подтверждён коммитами, тестами и сохранёнными отчётами.
- По уточнению пользователя выбран Appwrite вместо Supabase.
  Схема создана штатной консолью, ключ ограничен rows.read/rows.write.
- Счётчик Appwrite в smoke запрашивается явно через total:true;
  не полагаемся на значение по умолчанию нового SDK.
- SSO-защита Vercel не менялась: production-алиас публичен при стандартных
  настройках. Ключ заменён и сохранён как Secret; первоначальный ключ отозван.

Все созданные записи — демонстрационные; денежных списаний нет.
