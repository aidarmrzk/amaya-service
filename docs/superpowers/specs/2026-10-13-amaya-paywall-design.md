# Amaya: мобильный paywall — спецификация

Дата: 2026-10-13. Проект: C:\projects\amaya-service.

## Цель и границы

Выполнить тестовое задание из PDF: один мобильный экран детской игры,
макет Figma, Nuxt 4 + TypeScript с работающими server routes,
сохранение тестовой покупки в постоянной БД, живой деплой,
репозиторий GitHub и README до одной страницы.
Это демонстрация для проверки разработчика. Покупки тестовые,
денежные списания и платежные SDK отсутствуют.
Ориентир задания — два часа: сначала основной сценарий и серверная часть,
ограничения и непроверенные пункты честно фиксируются в README.

## Выбранный подход

Один Nuxt-проект объединяет frontend и backend. Appwrite Cloud TablesDB
хранит покупки независимо от жизненного цикла функций Vercel.
Vercel публикует Nuxt с серверными маршрутами.
SQLite на файловой системе Vercel не подходит для постоянного хранения;
раздельные frontend/backend добавляют ненужную настройку.

## Дизайн и взаимодействие

Название: «Мир маленьких открытий». Язык интерфейса: русский.
Светлый кремовый фон, фиолетовый основной акцент, простой игровой персонаж
из векторных форм. Макет создаётся в Figma до реализации экрана.
Основной фрейм: 390 px; адаптация проверяется при 360, 390 и 430 px.
Одинаковые локальные шрифты, SVG, цвета и размеры используются в Figma и коде.

Экран содержит заголовок, краткое описание полного доступа,
две карточки тарифов, CTA «Открыть полный доступ», ссылку
«Восстановить покупки» и пометку «Тестовая покупка. Деньги не списываются».
Тарифы: monthly — 299 ₽ за месяц; yearly — 1 990 ₽ за год.
Годовой тариф выбран по умолчанию и обозначен как выгодный.
Выбор выделяется рамкой, фоном и индикатором radio.
Цена и период видимы до покупки; обещания реального автопродления отсутствуют.
Минимальный размер основных зон нажатия — 44 px.
Учитываются safe area, прокрутка на невысоких экранах и клавиатурная навигация.

Состояния: загрузка тарифов; экран выбора; ошибка загрузки с повтором;
покупка с заблокированным CTA; ошибка покупки с повтором;
успех с подтверждением открытого доступа; восстановление без покупки
с понятным сообщением. Важные изменения объявляются через aria-live.

## API и данные

GET /api/offers возвращает два тарифа с id, названием, суммой в копейках,
валютой RUB, периодом и признаком рекомендуемого тарифа.
Каталог определён на сервере; клиент не задаёт цену покупки.

POST /api/purchase принимает offerId и requestId (UUID).
Сервер проверяет тариф и тело запроса, получает условный идентификатор
устройства из cookie и сохраняет запись. Возвращает подтверждение
с id, offerId и createdAt только после успешной записи в БД.
Повтор того же requestId для устройства возвращает прежнюю покупку;
использование ключа с другим тарифом возвращает 409.
Некорректный запрос возвращает 400, недоступность БД — 503.
Cookie устройства генерируется сервером: HttpOnly, SameSite=Lax,
Secure в production. Это демонстрационный идентификатор, не авторизация.

POST /api/restore использует cookie устройства и возвращает последнюю
покупку либо purchased: false. Данные других устройств не выдаются.
Восстановление после удаления cookie не поддерживается и указано в README.

Таблица purchases: offerId enum (monthly/yearly), deviceId UUID,
requestId UUID. Дата/время — серверное поле Appwrite $createdAt.
ID строки — SHA-256(deviceId + ':' + requestId), первые 32 hex-символа;
уникальность ID обеспечивает идемпотентность при конкурентных запросах.
Индекс device_created по deviceId и $createdAt поддерживает восстановление.
Таблица и строки не имеют публичных permissions; включён rowSecurity.
Серверный API-ключ имеет только rows.read и rows.write.
Схема описана в appwrite.config.json; инструкции консольной настройки
и отдельный setup-скрипт для администратора хранятся в репозитории.
Серверные настройки находятся только в закрытом runtimeConfig и .env;
.env не коммитится. Используется отдельный бесплатный проект Appwrite,
существующие проекты и данные не изменяются.
## Проверка и сдача

Автотесты: корректная покупка; неизвестный тариф и некорректный UUID;
сбой БД без ложного успеха; повтор запроса без дубликата;
конфликт ключа с другим тарифом; восстановление для своего устройства
и отсутствие доступа для другого устройства.

Проверки проекта: TypeScript, тесты, production build.
Проверки браузера: выбор тарифа, loading/error/retry, успешная покупка,
восстановление, ширины 360/390/430, отсутствие горизонтального скролла.
Сопоставление скриншота 390 px с экспортом Figma при одинаковых шрифтах
и масштабе. Требование PDF 99% не объявляется выполненным без измерения;
результат сравнения и ограничения фиксируются явно.
После деплоя выполняется тестовая покупка через живой API,
проверяется реальная запись в БД и восстановление доступа.

Передача: ссылка на Figma с просмотром, публичный сервис,
репозиторий GitHub и README с запуском, структурой frontend/server/DB,
обоснованием платформ, применёнными AI-инструментами,
проверками и предложениями на следующие два часа.
Публикуются только файлы задания; личные файлы и секреты исключаются.
